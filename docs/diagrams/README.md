## Known disagreements between the pictures and the model

1. **Review workflow under-grades declared hops.** Seven arrows are dotted ("proposed, not in the model") although the ADL declares them as service reactions:
   - ProposalSubmitted → ProposalEnteredScreening
   - ConfirmEligibility → ProposalEligible / ProposalIneligible
   - AssignReviewer → ReviewersAssigned → ProposalUnderReview
   - SubmitReview → ReviewSubmitted
   - ProposalFullyReviewed → ProposalScored

   One revision reduced the count from 9 to 7 but did not fix it.
2. **Review workflow omits PanelDecision transition `decline -> declined`.** The chair's direct decline appears to dead-end at "decline · RecordDecline". In the model, and in the code, it publishes ProposalDeclined.
3. **Asynchronous delivery: the verification failure is a reading artifact.** The full name `AssignmentService.ReviewApi.MarkOverdue` is on the canvas, wrapped over lines, and the checker reads only the first line. The picture also leaves TriageProposed without a publisher; in the model it is published by the Triage workflow. The "if operand" edge label is meaningless.
4. **Authority boundaries does not show synchronous semantics.** The two cross-context calls are labelled only "invokes". They are synchronous and in-transaction: CallApi.GetCallStatus enforces INV-1 and IdentityApi.GetReviewerStanding enforces INV-12 (ADR-003). The "received by" arrows do not name their events.
